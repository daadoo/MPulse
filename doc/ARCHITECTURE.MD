## 1 工具简介
### 1.1 核心能力清单

- 主机基础指标：CPU 使用率、内存使用率、磁盘空间（分区使用率）
- 进程指标：Top 高占用进程（CPU / 内存排序）
- 定向业务观测：数据库进程资源消耗、Nginx 进程资源消耗、自定义服务 / 端口资源消耗
- 运行模式：CLI 一次性执行 / Daemon 常驻定时采集
- 输出渠道：控制台标准输出、本地日志文件
- 开放能力：HTTP API，对外提供结构化监控数据，便于对接告警、大屏、自研平台

### 1.2 非功能约束

- 单二进制发布，无外部运行依赖，方便直接 scp 部署到 Linux 服务器
- 低自身资源开销，监控本身不能明显侵占服务器资源
- 配置简单，支持命令行参数 + 配置文件
- 兼容主流 Linux（CentOS、Ubuntu、Debian）
- 采集周期可配置；Web 接口轻量化，不需要前端页面（只返回 JSON）

### 1.3 模块化分层
#### 入口层
- 【入口层】main 程序入口（模式分发：CLI / Daemon） ↓
- 模式判断：
  1. **CLI 模式**：收到 cli 参数，执行一次全量采集 → 输出结果 → 程序退出
  2. **Daemon 守护模式**：初始化调度器、启动 HTTP 服务、启动定时循环采集，常驻后台

#### 配置层
- 【配置层】配置解析模块 (config)↓
  读取配置来源，优先级：命令行参数 > 配置文件（yaml/json）> 默认值。
- 配置项包含：
  - 采集间隔（daemon 模式生效）
  - Web 监听地址与端口（默认 :55055）
  - 日志级别、日志文件路径
  - 需要监控的自定义端口列表、自定义服务名
  - 过滤规则：忽略哪些进程、忽略哪些磁盘分区
#### 调度层
- 【调度核心层】采集调度引擎 (scheduler)↓ 
- CLI 模式：调用采集器组，串行 / 并行执行一轮采集
- Daemon 模式：定时器（time.Ticker）驱动，按周期触发一轮采集；
- 管理采集结果容器，统一存放一轮采集的所有指标数据（内存结构体，默认不持久化数据库）
- 控制并发：采集器并行采集，减少指标采集耗时
#### 采集层
- 【指标采集层】各个采集器（Collector） ↓
- 1. `hostCollector`：主机 CPU、内存、磁盘分区使用率
- 2. `procTopCollector`：按 CPU / 内存排序，抓取 TOP 高占用进程（pid、名称、cpu%、mem%）
- 3. `nginxCollector`：匹配 nginx 进程，汇总 nginx 组的资源消耗
- 4. `dbCollector`：匹配数据库进程（mysqld/postgres 等，可配置进程名），统计数据库总消耗
- 5. `portCollector`：监听指定端口，找到端口对应的进程，统计该进程资源占用

#### 输出层
- 【输出&上报层】输出适配器（output控制台、日志、WebAPI）(output)

#### 公共包 `internal/model` & `internal/common`
- model：所有结构体定义（HostInfo、ProcessItem、MetricResult、ErrorInfo）
- common：常量、工具函数、时间格式化、单位换算（byte→GB 等）
